# Frontend state boundaries

The frontend lives in `frontend/`. It keeps Git-owned repository facts separate from interaction state. `frontend/src/lib/repository.ts` remains the semantic Tauri API; React does not parse Git output.

| State | Current owner | Examples |
| --- | --- | --- |
| Workspace registry | `frontend/src/App.tsx`, backed by Rust `workspace.rs` | Workspace list, registered repository paths, active IDs; persisted as app configuration |
| Repository session | `useRepositorySession.ts` for the active view; `repositoryCache.ts` for recent inactive snapshots | Open repository and HEAD, status, branches, active operation, conflicts |
| View | `App.tsx`, `HistoryPanel.tsx`, and their repository snapshot | Selected working-tree diff, selected history commit, active detail, refresh tokens |
| Layout | `frontend/src/layout/WorkspaceLayout.tsx` and `frontend/src/layout/workspace.css` | Detail position and size preset; both affect presentation only |
| Transient UI | The component that displays it | Dialogs, notices, pending confirmation, local form text, busy feedback |

Repository session updates use semantic reducer actions. A Git mutation result can update related repository facts in one transition. The shell still coordinates asynchronous operations and invalidates selected views explicitly. Feature panels keep local interaction state until a concrete cross-panel need calls for lifting it.

The shell shows the active workspace's registered repositories as tabs. The selected tab is frontend presentation state. A click restores its snapshot and mounted view in the same React update, then persists the selection and transfers the single watcher independently. Typed Tauri Git commands carry the selected repository ID. Rust resolves that ID against the Woo workspace catalog to a persistent `WorkingTree` for that repository; no Git command takes an arbitrary frontend path. Repository mutations share one gate across these sessions. `App.tsx` retains presentation snapshots by canonical repository path, so the same path in two workspaces shares one snapshot even though workspace repository IDs identify separate memberships. This cache is never persisted as Git truth.

Previously `resetRepositorySession()` discarded the active reducer state and a changing `HistoryPanel` key remounted the panel, losing commits, graph rows, pagination, selection, diff, and scroll. The cache now retains those values together with status, branches, operation/conflicts, repository-specific refresh tokens, active view, local file presentation, and commit draft. Layout detail position and size preset remain global; dialogs, pending confirmations, and operation busy state remain transient.

For a READY tab switch, React restores the cached session, toolbar, and view together. `RepositoryView` retains the previous React subtree and DOM for every visited, still registered repository, so History, graph, Changes, selected diffs, and scroll surfaces do not remount on return. The top-bar RemotePanel and sidebar BranchPanel are retained under the same repository key. Inactive views are hidden; in-flight remote operations keep their original repository ID and can finish while another tab is visible. The History ResizeObserver disconnects while inactive; conflict content requests are cancelled/ignored. Tag, stash, and remote enumeration resumes on activation or a relevant refresh token. Open tabs are pinned in `RepositorySessionCache`; its six-entry LRU limit applies to other unmounted snapshots. No mounted-view count limit is imposed pending actual memory measurements. Removing a repository from every workspace unmounts its view and prunes its cache entry.

A READY tab stays interactive while it revalidates. A truly COLD tab loads in the foreground; after the default tab has status and its first History page, the other open tabs prewarm one at a time with repository identity, status, branches, remotes, and the first History page with graph rows. Selecting a queued tab starts its foreground load immediately. The single watcher follows the selected repository after the tab is shown, and its events carry repository ID and session ID. Leaving a repository marks its snapshot stale without emptying it. On activation Woo compares HEAD/branch identity and revalidates status, branches, tags, and stashes in the background; unchanged refs avoid a Git history query. Changed HEAD or refs triggers a first-page history/graph reload while the old page stays visible until a coherent replacement arrives. A selected local diff is refreshed even when the file's status record is unchanged, because its content may have changed while the watcher was inactive. Request ID, watcher sequence, backend session generation, history request epoch, and cache refresh generation prevent late results from changing the active repository or overwriting newer data. A refresh failure retains cached content and shows a nonblocking error.

Only the most recently selected local and commit diff are retained per repository; repository removal releases the mounted view and snapshot. Scroll position is held by the mounted DOM, with the snapshot's pixel offset available for cold remounts. A commit-row anchor is used when a background first-page replacement contains the same row. A selected commit outside the refreshed first page is retained only if Git can still read that immutable commit; otherwise dependent selection is cleared. This checks object availability, not whether the commit is still reachable from a displayed ref. The sidebar's active tool and List/Tree modes are repository presentation state. The existing `App.tsx` still coordinates semantic mutation results and targeted invalidation; future refactors can extract those workflows one at a time without changing Git ownership.
