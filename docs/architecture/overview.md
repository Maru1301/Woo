# Architecture (M8)

M8 adds `remotes.rs` for one-process, NUL-delimited configured URL parsing and a semantic remote list. URLs returned to React are display hints with network paths, queries, and userinfo removed; the original Git configuration stays with system Git. `WorkingTree` owns one remote operation slot with an ID, queued/running/terminal phase, start time, elapsed time, cancellation signal, and targeted refresh result. Tauri exposes only list/start/status/cancel application commands. React polls an active operation and never builds a Git command.

The existing repository mutex serializes fetch, pull, and push with stage, commit, checkout, and repository opening. Already loaded UI remains usable; new backend Git reads can wait behind a remote operation. Opening another repository requests cancellation first, then takes the session lock. Pull success or failure refreshes branches, HEAD, and status and resets history/graph and diff selection. Fetch and push refresh branches and reload history page one for ref decoration without clearing the selected commit snapshot; neither reloads working-tree status or invalidates an in-flight file diff. A failed or cancelled operation also refreshes affected state because Git may have made partial changes. If refresh fails, the UI asks the user to reopen the repository instead of presenting stale state.

`GitRunner::run_remote` uses direct Git invocation, null stdin, and `GIT_TERMINAL_PROMPT=0` while retaining configured credential helpers, SSH, and Git options. It drains stdout/stderr concurrently with 64 KiB/256 KiB capture bounds. No normal remote timeout is imposed; the runner accepts an explicit optional timeout. Cancellation kills and reaps the Git child; on Windows it uses `taskkill /T /F` to stop descendants that otherwise keep pipe handles open. Captured Git URLs are redacted before errors reach React. The operation slot stores only the latest operation, not an activity history.

Woo uses React and TypeScript for display, input, and local interaction state. React invokes asynchronous application commands and receives structured models or `AppError`. It neither executes Git nor parses Git output.

The Rust repository module owns repository validation and interpretation of Git results. The Git runner invokes installed `git` directly with structured arguments, a working directory, null stdin, a configurable timeout, and child cleanup on cancellation. It returns bytes, exit status, stderr, and elapsed time. The repository layer turns these into user-facing models and errors.

`open_repository` checks that the input is a directory inside a working tree, asks Git for its root, branch, and latest commit, and returns a usable result for unborn branches and detached HEAD. Bare repositories remain outside scope. No repository-wide history or diff is loaded.

M2 adds `WorkingTree`, a single-repository session holding the currently opened root behind an async mutex. The mutex serializes repository switches, status reads, and index mutation plus targeted status refresh. Each stage/unstage command returns the refreshed status in one application operation. `git status --porcelain=v1 -z --untracked-files=all --renames` runs once per refresh. `status.rs` parses its byte output into staged, unstaged, untracked, and conflicted changes. React receives paths and semantic change kinds, never porcelain codes. Status loading and index mutation use the same Git runner with a 60-second timeout. There is no watcher or cache yet.

M3 adds a commit operation to the same serialized session. Rust rejects blank messages, unresolved conflicts, and an empty staged index before invoking Git. The process runner sends the message bytes to stdin for `git commit --cleanup=verbatim -F -`; shell quoting and temporary message files are unnecessary. A longer 300-second commit timeout allows normal hooks and signing. On success, one Git read obtains HEAD and one status read updates the working tree; the command returns both in `CommitResult`. React replaces its displayed HEAD and status from this one result. The branch is unchanged by a normal commit, so no extra branch read is made.

Staging uses `git add -A`; unstage uses path-scoped `git reset -q --`, which also works before the first commit. Individual paths use `--literal-pathspecs` and reject absolute/parent paths. Renames pass destination and source paths together. Git's own index lock handles outside processes; Woo serializes its own operations.

Important files: `src-tauri/src/git.rs` (process and stdin), `src-tauri/src/repository.rs` (repository and HEAD read), `src-tauri/src/status.rs` (parser/model), `src-tauri/src/working_tree.rs` (session/operations), `src-tauri/src/error.rs` (error contract), `src-tauri/src/lib.rs` (Tauri commands), `src/lib/repository.ts` (typed frontend boundary), `src/App.tsx` (UI).

M4 adds `history.rs` for bounded Git log execution, byte-delimited parsing, and pagination. The application command accepts an opaque cursor and returns commit metadata only: hash, all parents, author, timestamp, subject, and decorated refs. It never loads patches or complete bodies. `WorkingTree` snapshots the repository path and generation, releases its mutex while Git runs, and rejects the response if a repository switch intervenes. `HistoryPanel.tsx` owns the virtualized list and selection; it is keyed to the open repository and HEAD so a successful commit starts a fresh history request. History loading does not delay repository opening or working-tree status.

The log format is `%H%x00%P%x00%an%x00%ae%x00%aI%x00%s%x00%D` with `-z`, `--all`, `--decorate=short`, and topological/date ordering. The Rust parser splits NUL fields and records. `%D` decorations split on comma-space, which cannot occur inside a Git ref name. Ref labels remain presentation strings, including `HEAD -> main` and `tag: v1`; full ref classification is deferred. Invalid UTF-8 history metadata returns a structured error.

M5 adds `diff.rs`. A selected working-tree file uses a targeted `git diff`; a selected commit first loads a NUL-delimited `--name-status` file list, then loads one selected file's patch. Root commits diff against the empty tree. Merge commits use Git's first-parent diff mode, and the UI states that interpretation. The parser turns one targeted patch into file, hunk, and line models with old/new line numbers, no-newline markers, and binary state. React never parses patch text. Git runs through the existing runner; its bounded-output mode kills a patch process after 2 MiB of stdout. The parser also caps text at 20,000 diff lines. There is no diff cache or streaming yet.

Working-tree and commit diff requests snapshot the open repository generation and reject results after a repository switch. React clears a previous file selection after status mutation and uses component request cleanup to reject late responses when files or commits change. `DiffViewer.tsx` renders a fixed visible row window from the structured diff. Git patch paths are not parsed from human-oriented headers: the selected path and kind come from the existing status model or the commit's machine-readable name-status list.

M6 adds `branches.rs` and application commands for local/remote-tracking branch enumeration, creating a local branch, and switching to an existing local branch. One `git for-each-ref` process returns NUL-separated fields per newline-delimited ref; symbolic remote HEAD aliases are skipped. Rust derives branch names from full refs, preserving slashes and Unicode, and marks the current branch using Git's `%(HEAD)` atom. Detached HEAD remains explicit in `RepositoryInfo.branch = None`; a branch list does not invent a current branch. Upstream names are display-only metadata. No fetch or network operation is involved.

Branch creation uses `git branch -- <name>` from current HEAD and refreshes only refs. Checkout uses `git switch --no-guess -- <name>` so Git enforces working-tree safety and does not infer a new tracking branch. A successful checkout increments the repository generation, invalidating in-flight history and diff reads. Under the existing mutation mutex, Rust refreshes the branch list, HEAD, and status and returns them in one `CheckoutResult`. React applies that result, clears the selected working-tree diff, and remounts history so its paging, commit selection, and commit diff return to the first page. This remount occurs even when switching between branches at the same hash. Git refusal leaves the existing UI state intact and displays the Git diagnostic. A successful switch followed by refresh failure requires reopening the repository, since the old UI state cannot be trusted.

This is the initial explicit state dependency contract: stage/unstage refresh status; commit refreshes HEAD and status, updates the current branch target hash from the returned HEAD, and resets history; branch creation refreshes refs; checkout refreshes HEAD, refs, and status and invalidates history/diff selection. There is no watcher or generic event bus. Branch rows and history rows are virtualized separately. Branch request identities prevent late list responses from overwriting a newer repository or checkout result.

M7 adds `graph.rs`, a pure incremental layout over M4 `CommitInfo.hash` and `parent_hashes`. Each lane owns one expected future hash. When a commit arrives, the engine consumes its expected lane or takes the leftmost vacant lane for a new head. Its first parent keeps that lane when possible; further parents take vacant lanes or connect to an existing owner. A root frees its lane, and trailing vacancies are removed. Input order and Git parent order determine all choices. The layout returns compact `GraphRow` data (node lane, incoming flag, continuing lanes, ordered parent lanes, width), without copying commit metadata or computing pixels.

`CommitHistoryPage` now carries parallel `commits[]` and `graphRows[]` arrays. Its existing opaque cursor includes the active lane state after the page. The next request decodes that state and lays out only the next 100 commits; it does not relayout earlier pages or execute another Git command. The cursor is bounded and validated. HistoryPanel stores commits and graph rows together, so their indexes remain aligned. Its existing component remount after repository open, checkout, or commit also resets graph continuation and rejects old responses.

The virtualized history row contains one small SVG graph and its commit text in the same button and scroll surface. SVG translates semantic lanes into paths/circles; it does not decide topology. The gutter grows with loaded lane count up to 12 visible lanes. Wider histories retain complete Rust topology but clip distant lanes and show an overflow count, keeping commit text usable. Ref labels still come from M4 history metadata; no per-commit Git call was added. See ADR 0002 for the renderer decision.
