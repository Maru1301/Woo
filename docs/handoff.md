# Handoff

Current milestone: **M8 remote operations implemented. Stop before M9.** M1–M7 functionality remains in place. The React → Tauri commands → Rust application → Git runner → system Git boundary is unchanged.

M8 implementation: `src-tauri/src/remotes.rs` parses `git config --null --get-regexp '^remote\\..*\\.(url|pushurl)$'` as key/LF/value/NUL records in one process. `RemoteInfo` contains name and sanitized fetch/push URL hints. It preserves local versus remote refs through the existing branch model; it does not contact remotes for enumeration. Multiple configured URLs remain under Git's control; M8 displays the first of each kind. URL authority userinfo, network path, query, and fragment are withheld from React, and URL-like Git diagnostics are masked. `src-tauri/src/lib.rs` exposes `get_remotes`, `start_fetch`, `start_pull`, `start_push`, `get_remote_operation`, and `cancel_remote_operation`, never a generic Git command.

Commands/semantics: fetch is `git fetch -- <configured remote>` without pruning; pull is argumentless `git pull`, respecting Git's configured merge/rebase/fast-forward policy and never stashing/resetting; push is argumentless `git push`, respecting upstream/push.default and never forcing or implicitly setting upstream beyond Git's own configuration. A configured-name validation process precedes fetch so a frontend caller cannot use an arbitrary URL. Pull or push without suitable upstream follows Git's error. All operations use the existing repository mutex, so Woo's stage, commit, checkout, open, and remote operations cannot race on the same session. Already rendered UI remains interactive; new Git reads may queue behind a remote process. Opening another repository requests cancellation before waiting for the lock. Component unmount and history request epochs reject late old-session responses.

Long-running infrastructure: `GitRunner::run_remote` accepts an optional explicit timeout, uses null stdin and `GIT_TERMINAL_PROMPT=0`, preserves Git credential helpers/SSH/configuration, drains stdout/stderr with 64 KiB/256 KiB capture caps, and kills/reaps on cancellation. On Windows, `taskkill /T /F` terminates the Git child tree so helper/SSH/hook descendants do not leave pipes open. `RemoteOperationStatus` has ID, kind, queued/running/completed/failed/cancelled phase, start/elapsed time, Git/refresh durations, optional structured refresh, and sanitized error. Only the latest operation is retained. The frontend polls every 300 ms, offers Cancel, and shows elapsed state without inventing a percentage. Git may legitimately show a configured credential-manager or SSH askpass UI; terminal fallback is disabled. Live credential-manager/SSH authentication was not automated.

Refresh/invalidation: successful or failed fetch refreshes branches and reloads history/graph page one for refs; selected commit metadata/diff snapshot is retained. Push does the same because local remote-tracking refs or upstream may change. Neither fetch nor push refreshes status or clears a working-tree diff. Pull, including a conflict/error after partial mutation, refreshes branches, HEAD, and status, resets history/graph page one, and clears stale working-tree diff. Pull bumps the repository generation so in-flight history/diff responses are rejected. A refresh failure tells the UI to reopen rather than showing stale state. The frontend applies Rust's `RemoteRefresh` contract instead of constructing Git refresh sequences.

Clone derives on existing small models support operation-status polling.

Verification: frontend production build passed. The full Rust suite passed with 52 tests (20 unit, 32 integration), followed by a focused no-remotes integration test added afterward; all 53 distinct tests passed. Remote tests use a temporary bare remote plus two clones and cover fetch worktree preservation, pull HEAD/status/history refresh, push, non-fast-forward refusal, no upstream, failed pull conflict refresh, missing remote, cancellation, and timeout. Parser tests cover empty/malformed config, separate fetch/push URLs, dotted/Unicode names, and credential redaction. `cargo fmt --check` passed. Clippy with `-D warnings` passed when three pre-existing M4/M7 style lints were allowed (`manual_is_multiple_of`, `chunks_exact_to_as_chunks`, `useless_vec`); unqualified Clippy remains blocked by those pre-existing warnings. `npm run tauri -- build --no-bundle` built `src-tauri/target/release/woo.exe`, which stayed alive through a four-second launch smoke test. Native WebView control was unavailable, so visual button interaction and live credential prompts were not smoke-tested.

Diagnostic timing: a local Windows debug sample measured fetch Git 255 ms + branch refresh 40 ms (397 ms test wall including preflight/poll), pull Git 350 ms + HEAD/status/branch refresh 142 ms, and push Git 343 ms + branch refresh 49 ms. Fetch uses three Git processes including validation, pull four, push two. These are local fixture diagnostics, not network speed or UI frame measurements. No Fork comparison.

Known limitations/debt: code review found no remaining critical M8 defect. Only the latest operation is queryable; no persistent activity history or percentage progress. Windows cancellation depends on `taskkill`; Unix kills the Git child but has no explicit descendant-tree kill yet. Forced cancellation of a mutating pull can leave Git conflict/lock state, which Woo refreshes or asks the user to reopen. Remote URLs shown to React are sanitized hints; advanced multi-URL remote management remains out of scope. Live credential helpers, SSH askpass, native WebView remote interaction, and actual scrolling frame times need manual verification. M4 deep skip pagination, M5 diff IPC/serialization cost, M6 many-ref variability, and M7 native scrolling measurement remain prior debt.

M9 recommended starting point: first choose the next product capability deliberately. Before expanding remote workflows, manually smoke-test credential-manager and SSH prompts in a real Tauri window and measure native operation feedback/scrolling. If long-running workflows grow, split the single operation slot into a small Activity Manager with bounded history; do not prebuild it now.

## Previous M7 summary

Completed through M7: repository open, status/staging, index-only commit, paged history, on-demand structured diffs, safe branch workflow, and incremental commit graph. The React → Tauri → Rust application → system Git boundary remains intact. Graph layout is pure Rust application computation over M4 commit metadata; no Git process or patch retrieval was added for graph rows.

Graph input/model: M4 `CommitInfo.hash` and ordered `parent_hashes` are the only topology input. `GraphRow` has `node_lane`, `lane_count`, `incoming`, `continuations`, and `parent_lanes` in Git parent order. It contains no duplicate commit metadata or pixel coordinates. Each `CommitHistoryPage` carries parallel `commits[]` and `graphRows[]`; array position is the link.

Layout: `src-tauri/src/graph.rs` processes newest-to-oldest topological history deterministically. An active lane owns exactly one expected future hash. A matching commit consumes that lane; an unrelated head uses the leftmost vacancy or appends. The first parent inherits the node lane unless it already has an active owner. Additional parents use existing owners or vacant lanes in parent order. Root commits terminate their lane. Trailing empty lanes are removed and internal vacancies reused. Every parent gets one ordered target lane, including octopus merges. The engine rejects malformed hashes, duplicate parents, duplicate commits within a page, duplicate lane ownership in a cursor, and more than 4,096 simultaneous lanes rather than drawing misleading output.

Pagination/lifecycle: the M4 opaque cursor now includes serialized active lane ownership after a page; the next request validates it and lays out only its new 100 commits. The predecessor check from M4 remains. Cursor input is capped at 300 KB. Repository open, commit, checkout, and history reload remount/reset `HistoryPanel`, discarding history and graph continuation together; existing generation/epoch checks reject stale responses. M4 deep skip-based Git pagination remains unchanged.

Renderer: `src/GraphRowView.tsx` draws semantic lanes as SVG in the same virtualized button and scroll surface as commit metadata. React never assigns lanes. Node/edge colors are deterministic by lane index; refs remain M4 labels. The gutter grows with loaded width through 12 visible lanes, then clips distant geometry and shows the hidden-lane count. Rendering paths are filtered to visible lanes; a 1,000-parent synthetic row produced only 12 visible paths. ADR 0002 records why row SVG was chosen over Canvas for M7.

Files changed for M7: `src-tauri/src/graph.rs`, `history.rs`, `lib.rs`, `tests/history.rs`, `examples/bench_graph.rs`, `examples/bench_history.rs`; `src/GraphRowView.tsx`, `HistoryPanel.tsx`, `lib/repository.ts`, `style.css`; `scripts/bench-graph-render.mjs`; architecture, performance, ADR, and this handoff.

Verification: frontend production build passed. Rust formatting check and all 42 Rust tests passed (18 unit, 24 integration). Pure graph tests cover linear/root, divergence/merge, nested/repeated merges, octopus, deterministic page continuation, internal lane reuse, and invalid state. Git integration tests cover linear and merge history plus a merge lane crossing the 100-commit page boundary; two incremental pages exactly match one continuous layout. The Tauri release executable built with `--no-bundle` and stayed running through a four-second launch smoke test.

Performance: five-sample median debug Rust layout totals: linear 1,000 commits 1.830 ms; linear 10,000 20.264 ms; 50-branch 10,000 56.108 ms; repeated-merge 10,000 24.683 ms. The slowest measured 100-commit page was 1.042 ms (50 branches). First-page graph JSON was 8.2 KB linear and 18.5 KB at 50 lanes; max 50-lane continuation token 2,049 bytes. Integrated 10,000-commit linear first page: Git 63.701 ms, parser 0.271 ms, graph 0.348 ms, total Rust 64.429 ms, JSON serialization 1.927 ms, full page 32,458 bytes. Git remained dominant. No Fork comparison.

Scrolling diagnostic: the production SVG component was rendered at 100 virtual scroll positions across 10,000 loaded synthetic rows. At most 16 SVGs and 144 paths existed per position; median server-side React render 1.756 ms, worst 14.783 ms including cold work. This verifies bounded rendering, not WebView frame time. Native computer-use could not connect to its Windows helper after retry/reset, and no controlled browser was available. Actual visible scrolling, dropped frames, Tauri IPC, and paint remain unmeasured.

Known cases/debt: histories needing more than 12 simultaneous visible lanes show an overflow count and clip distant geometry, while keeping complete topology data. More than 4,096 active lanes returns a structured graph error. Shallow/grafted histories with parents absent from the queried history may leave continuation edges at the final row. Loaded M4 commit/graph arrays still grow with pages; deep offset pagination can revisit skipped commits. M5 diff IPC/render measurements and external repository watching remain prior debts. No significant M1–M6 regression or architectural blocker was found in review.
